# 服务器使用必读手册（EvoTree）

> ## 🔴 第一铁律：绝对不碰别人的任务
>
> 这是一台**多人共享的 root 机器**，多个项目同时在上面跑任务。用 root 登录意味着**你能看到、能删掉所有人的东西**。曾经发生过误删他人运行中容器的事故，下面每一条都是为杜绝这类情况定的，违反任何一条都可能毁掉同事几天的工作。
>
> **1. 清理只用「精确名字/ID」，绝不用「批量/差集」。**
> - ❌ 永远不要：`podman rm -f $(podman ps -aq)`、`for c in $(podman ps -aq)`、`pkill -x qemu`、`pkill -f qemu`——**这些会杀光所有人的容器/虚拟机**。
> - ❌ 永远不要用「拍快照→删掉不在名单里的」这种差集清理——**数据源一旦返回空，就会把别人的全删**。
> - ✅ 只用：`podman rm -f <你自己的确切容器名>`、`kill <你自己的确切PID>`。删之前先 `podman ps -a` 用眼睛确认这个名字/ID 是你自己的。
>
> **2. 给自己的东西打独有前缀，从名字上就和别人分开。**
> - 容器、tmux 会话、临时文件，一律用 `evo-` / `rh-` 前缀（如容器 `evo-osworld`、会话 `rh-train`）。
> - 这样"你的"和"别人的"一眼可辨，清理时只认自己的前缀。
>
> **3. 动手前先拍照，先看清现场再操作。**
> - 起任何容器/进程前，先 `podman ps -a` 和 `pgrep -x qemu` 看清「现在有哪些是别人的」。
> - 凡不是你自己前缀（`evo-`/`rh-`）的容器、跑了很久的 qemu、别人的 GPU 进程——**一律当作碰不得，绕开，不删不杀不动**。
>
> **4. `pkill -f "关键词"` 有自杀风险。** 它会匹配到你当前这条 SSH 命令自己（命令行里含那个关键词），把自己的 shell 杀掉（exit 255）。要按进程名精确杀用 `pkill -x <名>`，或先 `ps` 拿到 PID 再 `kill <PID>`；管理带特定 socket 的服务时，把命令写进脚本文件执行（脚本进程命令行不含关键词，避免自匹配）。
>
> **5. 收工先清自己的残留、释放资源。** 跑完 `podman ps -a` / `pgrep -x qemu` / `nvidia-smi` 确认自己没留下容器、qemu、GPU 占用、多余的 podman service。清的时候还是只清自己前缀的。
>
> **一句话：这台机器上除了你自己 `evo-`/`rh-` 前缀的东西，其它一律不碰。宁可留下自己的垃圾没清，也绝不多删别人一个。**

```bash

cd /data/songweishuai/envs
uv venv evotree --python 3.11

# 激活 + 装依赖
source /data/songweishuai/envs/evotree/bin/activate
cd /data/songweishuai/projs/rh/EvoTree/proj/EvoTree
uv pip install -e .
```

## 几条提醒

- **全员用 root 登录**：操作前看清路径，`rm -rf` 三思，别误删别人的东西 —— 详见顶部 🔴 第一铁律。
- **长任务用 tmux**：`tmux new -s rh` 起会话，断连也不掉；回来 `tmux attach -t rh`。
- **跑之前 `nvidia-smi`**：挑空闲卡，`export CUDA_VISIBLE_DEVICES=0` 指定用哪张。
- **别往 home 塞大东西**：环境、模型、数据都放 `/data/...`。
