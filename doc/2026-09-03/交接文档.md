### 1.2 P0：边级成败 vs 轮级成败（本地 `03ca8eb` / A800 `9962411`）

**这是最严重的语义 bug。** 详见 `proj/EvoTree/doc/spec/2026-09-03/08_边级成败修复.md`。

一句话：`write_episode` 原先把 `episode.success`（整轮成败）套到每一条边，导致
`p(e)` 变成 episode 级成功率而非 idea §0 定义的边级成功率。后果是 idea §8 贯穿
示例无法复现、`to_fail` 永不赋值、整轮失败的轨迹前瞻断链（对 RQ3 零贡献）。

修法：`EpisodeStep.action_success`（边级，工具报没报错）决定 `n_success` 和落点
指针；`Episode.success`（轮级）只决定要不要记 cost-to-go。判据统一到
`distill_osworld.extract_error_note`，在线/离线共用。顺带修了 `reset()` 丢首帧。

实测复现 §8：越界的 `duplicate_slide` 边 `p=0.00 to_fail=s2`，失败落点有自己的
出边；整轮失败的轨迹前瞻恢复可用。

### 1.3 P1：τ 任务模板库（本地 `f52b4d0` / A800 `028be24`）

新增 `proj/EvoTree/evotree/template_lib.py`。修两个缺陷：

- **假合并**：旧实现把骨架截断到 40 字符做 template_id，长指令共享前缀就碰撞。
  现在 id = 可读前缀 + 完整骨架 SHA1。
- **假分裂**：只挖引号/文件名/数字，挖不到的可变词（列名）导致同模板分家
  （idea §4.1 的 Revenue/Cost 原例）。现在模板库对"只差 ≤1 个可槽位化词"的
  骨架做二次归并。

**没用 embedding**（VM 内跑评测、依赖走离线 wheelhouse，不该加 GPU 依赖），用
词级骨架 + 位置差异逼近，保持确定性。接口按 embedding 版预留，换向量余弦即可升级。

模板库随记忆持久化到 `memory/templates.json`（idea §9 要求，之前缺失）——**必需**，
否则树按 id 存盘但库丢了，重启后同一指令会新开一棵树、历史经验失联。

顺带修 `normalize.py` 文件名正则误伤：`python3.11 — Terminal`、`github.com/foo`
以前被错误归一化成 `<file>`，会把不同应用/网站窗口混成同一状态。

> **重要更正**：我一度判断"τ 假合并会毁掉 20 任务实验"，据此建议先修 τ 再跑。
> 后来用真实 20 条 os 域指令实测，**新旧实现都是 20 任务→20 棵树、零碰撞**，
> 假合并在这批数据上没实际发生。τ 修复的真实价值是假分裂 + 模板库持久化 +

## 2. v3 实验：正在跑什么，怎么看，跑完怎么办

### 2.1 为什么是 v3

v1 端口冲突作废（产物标 `INVALID-*-port-collision`）。v2 卡死在 VM 内联网装
fastmcp+playwright——`waiting for deps install...` 刷了 2h43m，20 任务只完成 5 个。

装依赖压到 2.5 分钟。冒烟已验证这条生效（见 2.4）。

### 2.2 三个 arm 是什么（不是"跑三遍"）

`run_arm.py:18` `ARMS = ("baseline","frozen","online")`。20 任务各跑一次，跑三组，
差别只在记忆：

| arm | 记忆 | 回答 |
|---|---|---|
| baseline | 无 | 裸模型难度，用于给任务分难度桶 |
| online | 边跑边写（从空 memory 起） | 积累经验过程中有没有变好 |
| frozen | 只读 online 的最终 memory（关写入） | 攒好的记忆迁移到只读还有没有用 |

串行接力：baseline 独立脚本先跑 → online → frozen 复制 online 的
`memory/env-0` 并 `--no-evotree_write_enabled`。frozen 前后 memory SHA-256 必须
完全一致（证明只读没污染种子）。

> **这轮不能报"记忆净增益"**：idea §5 要求的"记忆禁用、同样重复 3 轮"对照基线
> 还没做（见待办 P2）。没有它，online 的提升分不清是记忆功劳还是任务重复曝光。
> 这轮的定位是"修复后能不能完整跑完 20 任务" + 给难度分桶提供数据。

- **位置**：`evotree/retrieval.py` 取推荐的地方（约 `136-142` 行，以当前文件为准）。
- **做法**：val=0 或 n_success=0 的边不进 `recommendations`（但仍可留在森林里，
  只是不推荐）。注意别误伤未探索边（n=0，UCB 返回 inf 那种，语义不同）。
- **加测试**：一条崩溃边不出现在推荐栏。
