# Spec 2026-09-03 — 边级成败与轮级成败分离

## 问题

`write_episode` 把 `episode.success` 应用到轨迹里的**每一条边**，导致 `p(e)` 实际
是 episode 级成功率，而不是 idea §0 定义的边级成功率。

idea §8 Episode 1 把语义写死了：一轮**最终成功**的 8 步轨迹里，越界失败两次的
`duplicate_slide` 边应记 `n=3、p=0.33`，失败落点 `s_err` 有自己的出边 `n=2 p=1.0`。
修复前实测得到 `n=2、p=1.00`——**一条踩了两次坑的边被记成 100% 可靠**。

四层连锁后果：

1. 一轮成功的轨迹里 `to_fail` 永不赋值，§4.2 性质三（失败落点是带出边的正常状态）
   与 §7 主张四（成败全记）**结构上无法成立**；
2. 整轮失败的轨迹里所有边 `to_success` 恒为 `None` → 前瞻直接 return。失败经验对
   **RQ3 前瞻生死线零贡献**，与 §13 预期发现四（失败经验边际贡献可能 ≥ 成功经验）
   正好相反；
3. `steps_after_success` 被追加给轨迹里每一条边（含实际失败的绕行步），cost-to-go
   被污染，`val` 的效率项把踩坑代价算成了路径长度；
4. RQ1/RQ3 的核心量 `val` 建立在错误的 `p` 上。

代码里对此有过一段自辩：OSWorld 中间 `reward=0` 不代表单步失败。这个观察是对的，
但解法走偏了——文档要的"这一步成没成"是**工具有没有报错**，不是 reward。而错误
信号**代码本来就在提取**（`osworld_integration._note_from_step`、
`osworld_adapter._extract_note`），只是拿去写 notes 而没有用来定成败。

## 改动

**语义分离**：`EpisodeStep` / `RuntimeStep` 新增 `action_success`（边级），与
`Episode.success`（轮级）分开，对应 idea §0 写入的两个不同步骤：

| | 数据 | 决定 |
|---|---|---|
| 第 3 步（边级） | `EpisodeStep.action_success` | `n_success`、`to_success`/`to_fail` |
| 第 4 步（轮级） | `Episode.success` | 要不要记 `steps_after_success` |

cost-to-go 只统计**走通了的**步（`episode.success and step.action_success`），
失败的绕行步不计入"还差几步到终点"。

**统一错误判据**：新增 `distill_osworld.extract_error_note`，在线 wrapper 与离线
adapter 共用。此前两份判据不同（离线不看 `exe_result`，在线不把 client error 记
成 note），同一条轨迹走两条路径会写出不同的 `global_notes`，让 M2 的 online/frozen
两臂不可比。

**reset 丢首帧**：`EvoTreeEnvWrapper.reset()` 把 `_last_observation` 清成 `None`
且不回填。runner 走 `obs = env.reset()` 拿首帧时（OSWorld 常见写法），第一个动作的
`before` 观测为 `None`，**整步被静默丢弃**且不报错。旧测试因为显式调了 `_get_obs()`
而掩盖了这条路径。

**顺带**：`osworld_adapter` 改用 `dataclasses.replace` 重建 step，避免以后加字段
时漏传；`tests/test_episode.py` 整个文件曾被复制粘贴两遍（后半静默覆盖前半），已合并。

## 验证

复现 idea §8 Episode 1（查页数 → 越界失败 ×2 → 修正成功 → save，整轮成功）：

```text
s0  get_slide_count   n=1 n_succ=1 p=1.00 to_succ=s1 to_fail=None steps=[3]
s1  duplicate_slide   n=1 n_succ=0 p=0.00 to_succ=None to_fail=s2  steps=[]
s2  duplicate_slide   n=2 n_succ=1 p=0.50 to_succ=s3  to_fail=s2   steps=[2]
s3  save              n=1 n_succ=1 p=1.00 to_succ=s4 to_fail=None steps=[1]
```

- 越界的边 `p<1` 且 `to_fail` 已连 ✅（修复前 `p=1.00`、`to_fail=None`）
- 失败落点 `s2` 有自己的出边统计 ✅
- `steps_after_success` 只含走通的步（3/2/1），踩坑那步是 `[]` ✅
- 整轮失败的轨迹 `to_success` 正常保留，前瞻可用 ✅（修复前前瞻断链）

本地与 A800 canonical repo 全量 pytest 均为 **148 passed**（原 141 + 7 个新增
语义/回归测试），九个改动文件两边 SHA-256 逐一一致。

## 尚未处理（按优先级）

- **P1 τ 仍是占位实现**：三条正则替换，无 embedding/模板库/槽位可填性判定。
  `_slugify` 截断到 40 字符会**假合并**——实测 `rename the directory foo to bar`
  与 `rename the file report.txt to final.txt` 撞进同一棵树，违反推论 2。
  同时会**假分裂**：同模板不同列名（Revenue/Cost）分到两棵树。
- **P1 val=0 的边仍进推荐栏**：`retrieval` 无条件取 top-k，一条 `n=1 p=0.0`
  的崩溃工具会被推到候选首位，污染 RQ4 冷启动口径。
- **P2 GUI α 用动作类型而非语义描述**：所有点击归成同一条边，粒度粗到没有决策
  价值，且 D5「GUI 归堆更脏」的 claim 落空、RQ5 消融无对象可测。
- **P2 facts 未作为选边 side-condition**：D1 要求 facts 在第 ② 拍参与选边，
  代码中从未读取。
- **P2 §5 缺「记忆禁用、重复 3 轮」对照基线**：当前 baseline 是单轮无记忆，
  报不出净增量，进化 claim 有混淆风险。
