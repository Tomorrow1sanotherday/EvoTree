# 20 任务三阶段实验设计

## 目标

此前五任务评测只验证了工程闭环，任务数量太少，且简单任务存在天花板效应，
不能据此判断 EvoTree 是否带来经验收益。本轮固定 20 个 OSWorld `os` 域任务，
先校准裸模型难度，再进行在线积累和冻结复测。

任务清单固定在：

```text
experiments/m2_small_eval/tasks_20.json
```

所有阶段使用同一个模型、任务顺序、`max_steps=8`、单环境 CPU/TCG 配置。

## 三阶段

1. `baseline`：不传 `--use_evotree`，用于得到 20 个任务的裸模型难度。
2. `online`：从空目录复制 seed，启用 EvoTree 写入；经验只能来自本轮此前已完成的
   任务，不使用历史 M1/M2 memory。
3. `frozen`：复制 online 结束后的 `memory/env-0`，传
   `--no-evotree_write_enabled`，在相同 20 个任务上只读复测。

online 从空 memory 开始，因此清单中即使包含曾用于旧实验的任务，也不会读取旧
seed，不存在历史 memory 泄漏。frozen 的输入则有意使用本轮 online 产生的最终
memory，用于测量积累后的记忆能否影响后续决策。

## 运行目录

```text
baseline: /data/songweishuai/evotree_m2_baseline20_20260902
suite:    /data/songweishuai/evotree_m2_20tasks_20260902
stage:    /data/songweishuai/evotree_m2_20tasks_20260902.stage
```

baseline 完成后由串行接力器启动 online 和 frozen。接力器只检查并清理本实验的
精确 `evo-m2-*` 容器名；容器查询失败时中止，不触碰其他容器或 QEMU。runner
已有 `result.txt` 断点过滤能力，完成任务不会重复执行。

## 报告指标

`experiments.m2_small_eval.report` 在原有逐任务 evaluator score、成功率和有效动作
统计上增加：

- `experience_prompt_hits`：真实保存的模型 prompt 中出现 `[经验]` 的步骤数；
- `caution_prompt_hits`：真实保存的模型 prompt 中出现 `[注意]` 的步骤数；
- `memory_changes`：memory 文件的前后数量，以及新增、删除、内容修改数；
- baseline 独立脚本的纯文本 `returncode` 也纳入基础设施完整性判定。

最终报告同时给出 20 任务总体结果和 baseline 中等/困难子集结果。不能只比较总
平均分；还要核对 frozen memory 前后完全一致，并确认经验段确实进入真实 prompt。
