## 一、distill.py —— 三道清洗

- **接口与实现分离**：`Distiller` Protocol 定义三个方法；`RuleBasedDistiller`
  是占位实现。真实的 embedding/VLM 版按接口替换，不动上层。
- **每个方法标 `TODO(B阶段)`**：说明真实实现要改什么（τ 用 embedding 聚类、
  φ 用 a11y tree + VLM、α 从 function-calling 解析）。
- **占位策略**：
  - τ：把引号内容/文件名/数字替换成 `<argN>` 槽位，相同骨架归同一模板。
  - φ：从 observation dict 直接读 app/window/dialog（假设上游已抽好）。
  - α：工具 → 工具名+参数名槽位（值丢弃）；GUI → 语义描述（坐标丢弃）。

## 二、notes.py —— 注意栏

- `GlobalNotes`：`tool_name -> 去重笔记列表`。
- **硬规则**：只有 `query`（查坑），没有"推荐"方法 —— 结构上保证注意栏永不推荐。
- 冷启动兜底：全新任务经验树空，但注意栏照常命中别处学到的坑。

## 三、retrieval.py —— 五拍检索

- `Retriever.retrieve()` 执行五拍，产出 `Cheatsheet`（推荐栏 + 注意栏 + 重排）。
- **前瞻 k=1**（`_attach_lookahead`）：顺着 `edge.to_success` 指针跳到后继
  状态、取其最优出边 —— 这就是"森林 vs 平表"的分水岭（平表无指针）。
- `render_cheatsheet()`：渲染成注入 prompt 的文本，空栏整段不出现。
- 冷启动 = 推荐栏空返回（`is_cold_start`），不是特殊分支。

## 四、memory.py —— 顶层封装

- 对外只两个方法：`read(instruction, observation, candidate_tools) -> 小抄文本`、
  `write(instruction, trajectory)`。
- `write_enabled` 开关：Setting II 冻结评测时设 False（只读不写）。
- `write` 的连边逻辑：用"下一步的观测"作"上一步的落点"，末步单独入账；
  整轮成功则从终点倒数填 cost-to-go。

## 五、闭环 Demo（真实运行输出）

学 3 轮"复制列"任务后，同类任务读出的小抄：

```
[经验] 推荐：
  copy_cells(dst, src) —— 4次·成功率0.75·平均还差2步；完成后 save 一步收尾
      注意：
  copy_cells: dst out of range errors

reranked tools: ['copy_cells', 'delete_sheet', 'save']   ← copy_cells 被推到最前
```

方法的每个机制都在这张小抄里：记统计（4次·0.75·2步）、前瞻（save 收尾）、
注意栏（坑）、工具重排、双栏正交。

## 六、⚠️ 写代码过程中暴露的两个真实问题（有价值的发现）

### 1. 状态签名粒度（命中 idea 地基风险①）
测试 `test_lookahead_gives_next_step` 最初失败，暴露：**当连续两步的状态主键
(app,window,dialog) 相同时，两个动作会被建模成同一节点的"兄弟"出边，而非
"父子"，前瞻就断了。** 例：`duplicate_slide` → `save`，若两步 window 相同，
则 save 反而因剩余步数少而排在 duplicate 前面。

这正是 idea 反复强调的**地基①（签名可归并性/粒度）**：签名必须能区分动作
前后的局面。真实场景（同窗口内连续操作）很常见，**pilot 必须专门验证签名
粒度**。当前测试用 window 标题变化（`a.pptx` → `a.pptx *`）表达状态变迁。

### 2. φ 的 window 归一化（distill 占位版局限）
Demo 中新任务状态 `data2.xlsx` 与学习时 `data.xlsx` 的 window 主键不同 →
找不到当前状态 → 推荐栏空。说明 **φ 的 window 里的文件名应被归一化**（对
"复制列"任务，不同文件是同类状态）。这属于 B 阶段 distill 要处理的：主键
提取时把易变量（文件名等）归一化，与 τ 的槽位抽取对齐。

**这两个问题都不是 bug，是真实的建模挑战，且都在 idea 的风险清单里。代码在
实现过程中就把它们顶了出来 —— 正是好测试与真实数据对齐的价值。**
