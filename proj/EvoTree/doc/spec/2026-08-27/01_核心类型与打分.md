## 一、types.py —— 核心数据类型

整个系统的地基。其它所有模块都依赖这里。用强类型 `dataclass`，`frozen=True` 的类型可作字典键。

### 三个基本概念（三道清洗的产物）

| 类型 | 符号 | 含义 | 关键字段 |
|---|---|---|---|
| `Template` | τ | 任务模板"这是哪类活儿" | `template_id`, `skeleton`, `slots` |
| `StateSig` | φ | 状态签名"我在哪一步" | `app`, `window`, `dialog`（主键）+ `facts`（不进主键）|
| `ActionTmpl` | α | 动作模板"做了啥操作" | `kind`(TOOL/GUI), `name`, `arg_slots` |

**关键设计决策：**

- **`StateSig.facts` 不进主键**（对应 idea 决定 D1）。用 `field(compare=False)` 让它不参与 dataclass 的相等判定；`key()` 方法只返回 `(app, window, dialog)`。理由：主键必须确定性可提取（从 accessibility tree 读），facts 由 VLM 填、有噪声，进主键会污染归堆。

- **`ActionKind` 只有 TOOL / GUI 两类**，CLI 归入 TOOL（保证 TIR 口径与 OSWorld-MCP 官方一致）。

- **GUI 动作丢弃坐标**：`ActionTmpl` 里只存语义 `name`，不存坐标（坐标跨轮漂移，是经验不可复用的根源）。

### 两种记录（经验森林的组成）

| 类型 | 是森林里的 | 关键字段 |
|---|---|---|
| `StateNode` | 点 | `node_id`, `sig`, `visits` |
| `ActionEdge` | 边（**核心载体**）| `n`, `n_success`, `steps_after_success`, `notes`, `to_success`, `to_fail` |

**关键设计决策：**

- **`ActionEdge.to_success` 是"连起来"的指针**。前瞻（lookahead）靠它：从这条边的落点状态跳到那个状态的最佳后续动作。这正是"森林 vs 平表"的分水岭 —— 平表没有这个指针（对应 idea 推论 4）。

- **护城河一体现在 ActionEdge**：边上挂的是可数的充分统计量 `(n, n_success, steps_after_success)`，不是一句自然语言。

- **`edge_key()` 保证自动归堆**：同一 `(from, action)` 的多次执行落进同一条边，杜绝"挑最快那次记录"式的自欺。

- **派生值不存储**：`p = n_success/n` 和 `d = mean(steps)` 在 scoring 里现算，不存在 ActionEdge 里，避免冗余和不一致。

## 二、scoring.py —— 边价值打分（数学核心）

**全是纯函数**，不依赖任何可变状态。输入一条边，输出它的价值分。这样最好测、最好读。

### 公式（idea §0 唯一的公式）

```
p(e)     = n_success / n                    # 可靠性
d(e)     = mean(steps_after_success)        # 效率（剩余步数）
val(e)   = p(e) · γ^d(e)                    # 边价值 = 可靠性 × 效率折扣   (γ=0.9)
score(e) = val(e) + c · sqrt(ln N_s / n)    # 选边分 = 边价值 + UCB探索     (c=0.3)
```

### 函数清单

| 函数 | 作用 | 边界处理 |
|---|---|---|
| `success_rate(edge)` | p = n_success/n | n=0 → 0.0（无证据=不可靠）|
| `mean_steps_to_go(edge)` | d = mean(steps) | 无成功记录 → inf |
| `edge_value(edge, gamma)` | val = p·γ^d | d=inf → val=0 |
| `ucb_bonus(edge, N_s, c)` | UCB 探索项 | 未走过 → inf（最该探索）|
| `select_score(edge, N_s, ...)` | val + UCB | — |
| `is_low_confidence(edge, min_n)` | 样本太少？ | n<3 → True |

### 关键设计决策

- **脱钩声明（对应 idea D2）**：`val` **不是** Bellman Q。我们不做 value iteration、不假设 Markov 最优。γ 只是效率折扣权重，UCB 只是 bandit 探索。函数命名刻意用 `edge_value` 而非 `q_value`，避免"这是 RL"的误解。

- **无证据的边 val=0**：从没成功过的边（d=inf），效率项 γ^inf=0，直接 val=0。符合直觉：没有成功证据就不该被推荐。

- **未走过的边 UCB=inf**：鼓励探索未知边（idea §4.6 三道保险之一）。

- **`is_low_confidence` 直接呼应地基风险②**：361 任务/3 轮下每条边 n 可能只有个位数，n 小时成功率是噪声，必须让 agent 知道证据不足。

## 三、测试即文档

`tests/test_scoring.py` 的 15 个测试不只是验证，也是可执行的用法说明。两个特别重要的：

- `test_short_but_flaky_can_lose_to_long_but_reliable`：用数字证明 idea §4.2 的核心主张 ——「2步但0.3成功率」的路**不应**盖过「4步但0.95成功率」的路。算出来 0.243 < 0.590，可靠长路胜出。这防止方法退化成"只留最短路径"。

- `test_reliable_and_short_beats_reliable_and_long`：同样成功率下，短路径 val 更高（效率项起作用）。

运行：`cd proj/EvoTree && python -m pytest tests/ -v`（本地纯标准库即可，无需服务器）。
