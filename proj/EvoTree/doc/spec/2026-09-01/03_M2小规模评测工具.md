# Spec 2026-09-01 · M2 小规模评测工具

## 实验目标

M2 比较同一组 OSWorld 任务的三种运行模式：

- `baseline`：`use_evotree=False`，不创建 EvoTree runtime。
- `frozen`：从固定 seed memory 复制，启用检索但关闭写入。
- `online`：从与 frozen 完全相同的 seed memory 复制，允许整轮结果写回。

三组固定模型、API endpoint、任务顺序、`max_steps`、observation type 与单环境
CPU/TCG 配置。每个 arm 使用独立 results、memory 与精确命名的
`evo-m2-*` 容器，禁止并行启动。

## 任务清单

`experiments/m2_small_eval/tasks_smoke.json` 只含最大音量任务
`28cc3b7e-b194-4bc9-8353-d04c0f4d56d2`。

`tasks_5.json` 固定五个 OS 任务：

1. 设置 GNOME Terminal 默认尺寸。
2. 将系统音量调到 100%。
3. 放大 GNOME 文本缩放比例。
4. 从 Trash 恢复文件。
5. 开启 Do Not Disturb。

这些任务都在 `test_all_mcp.json` 的 OS 子集内，有对应 MCP 工具，同时可由 GUI
完成。真实 seed 所用的目录重命名任务被排除，避免直接重放同任务造成泄漏。

## 启动器

`run_arm.py` 每次只运行一个 arm：

- 不接受 `--api-key` 参数，只从子进程环境读取 `OSWORLD_API_KEY`。
- baseline 命令不含 `--use_evotree`；frozen 显式传入
  `--no-evotree_write_enabled`。
- frozen/online 在创建结果目录前验证 seed，再复制到各自的 `memory/env-0`。
- 输出 arm 已存在时立即失败，不清空、不覆盖、不续跑。
- 运行前后对 memory 内所有文件生成相对路径到 SHA-256 的 JSON manifest。
- provider 容器名由 label 和 arm 生成，固定使用 `evo-m2-*` 前缀。
- 只记录不含凭据的命令、时间和 return code；不自动清理容器或 QEMU。

最后一项是共享服务器安全边界：异常后的资源只能先查询归属，再按精确容器名或
已验证 PID 处理，启动器不会猜测并删除资源。

## 汇总器

`report.py` 从标准 OSWorld 结果层级读取 `result.txt` 与 `traj.jsonl`，输出每个
任务和 arm 的：

- evaluator score、完成/缺失状态与 success rate；
- 有效动作数、MCP tool 动作数、GUI 动作数；
- frozen/online memory manifest 是否保持不变。

轨迹解析直接复用 `OSWorldEpisodeAdapter`，所以 reset、DONE、terminate 与
client error 不计入有效动作，中间 reward=0 不参与整轮成败判断。

## 结构化执行动作修复

编写汇总测试时发现，真实 MCP `traj.jsonl` 的 `prediction` 可能包含多个或陈旧
tool call，而 `action` 字段明确记录最终执行的 `action_type/parameters`。旧版
`OSWorldDistiller` 总是优先取 prediction 的第一个 tool call，可能把实际执行的
MCP 动作误归为 GUI。

现在的优先级为：结构化 executed action > prediction tool call > 占位格式。
GUI 仍在没有结构化 action 时从 prediction 解析。测试覆盖“陈旧 GUI prediction
+ 实际 MCP action”和结构化 `computer_use.click` 两种情况。

## 测试

Windows 同步副本与 A800 正式仓库全量 pytest 均为 `136 passed`。测试覆盖三组
CLI 差异、API key 不进入命令、seed 复制与拒绝覆盖、缺失 seed 不占目录、稳定
memory hash、有效动作与 modality 汇总、缺失结果、`evo-m2-*` 容器名，以及不把
venv Python symlink 解析成底层解释器。
