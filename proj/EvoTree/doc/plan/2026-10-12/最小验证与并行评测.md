# 现有 EvoTree 的最小有效性验证

目标：先回答当前自动记忆机制是否有可重复的正向信号。保持当前
τ/φ/α、边统计、UCB、推荐过滤、单层前瞻和注意栏算法，不加人工经验。

## 两臂与轮次

固定 8 个原始、可完成的 OSWorld 任务：OS 2 个、Calc 3 个、Impress 3 个。
任务清单位于 `experiments/m2_small_eval/tasks_pilot_8.json`。文档任务包含
跨单元格、跨工作表、跨幻灯片操作，避免全部都是终端命令或单开关任务。
这些文档任务尚无本项目的基线成功率校准；若两臂全部失败，结果只能用于
诊断，不能据此否定记忆机制。

| 臂 | 第 1 轮 | 第 2 轮 | 第 3 轮 |
|---|---|---|---|
| baseline | 无记忆，独立 reset | 无记忆，独立 reset | 无记忆，独立 reset |
| online | 空记忆开始，读写 | 继承本分片第 1 轮的记忆，读写 | 继承本分片第 2 轮的记忆，读写 |

同模型 `gpt-5.6-terra`、截图观测、MCP 混合动作、`max_steps=15`。
总计 8 × 2 × 3 = 48 个 episode。各轮开始顺序交替：baseline→online、
online→baseline、baseline→online。两臂使用同一任务清单和并发数量。

每个 episode 重新初始化环境和 agent 对话。仅 online 记忆跨轮继承。
第 1 轮不是有效记忆收益的主要证据；第 2/3 轮与对应 baseline 的差值才是
主要观察对象。完整记忆持久化和每步检索日志保留，不能只看聚合成绩。

## 并行方式

4 个独立的一环境 runner，各固定 2 个任务；轮次之间保持分片不变。
每个 worker 使用独立容器名、5 个互不重叠的端口范围、输出与记忆目录。
同一阶段 4 个 worker 并行；所有 worker 的结果完整后才进入下一阶段。
不允许多个进程写同一份记忆，也不允许第 2 轮任务换到没有其经验的 worker。

本次 global_notes 仅在同一分片内共享，不做跨 worker 的合并。它与原串行
全局共享的协议存在差异；这是当前并行 pilot 的边界，报告时必须注明。

A800 的实际运行隔离是 Podman 容器内 QEMU，未发现 `/dev/kvm`。GPU 数量
不会直接加速 VM；主要通过 CPU 并发缩短总墙钟时间。4 路最多节省约 75%
墙钟时间是理想值，实际速度取决于 VM 冷启、磁盘、CPU 和模型 API。

## 判断与记录

主指标为 evaluator mean score 和完全成功率（score >= 1）。逐任务、逐轮
列出结果，以及 online-minus-baseline 差值。

辅助指标：成功与失败分别报告有效动作数，实际推荐/注意注入次数，失败
DONE、重复动作、MCP/GUI 动作数。步数下降不能单独当作方法有效证据。
超时、模型 API 错误、缺轨迹或 evaluator 结果的任务不当作正常的 0 分；
启动器拒绝把这类残缺轮次的记忆继续传给后续轮次。

8 个任务、单条三轮学习链只用于 pilot 筛查，不能支撑统计显著或完整
benchmark 增益的结论。若第 2/3 轮出现一致的优势，再复跑独立学习链并
扩任务；若无优势，先根据检索日志和动作轨迹判断是否命中、是否采纳。
前瞻开关、平表和文本经验消融放在最小有效性验证之后。
