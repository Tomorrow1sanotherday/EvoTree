# EvoTree 执行计划（Plan）

> 本文件回答一个问题：**我们现在应该先干什么。**
> 一句话总纲：**先花两周证明"方法能不能成立"（三条地基 + 前瞻消融），再决定要不要把它做完整。** 不先冲增益、不先堆功能——因为地基若是流沙，后面写多少代码都白费。

---

## 0. 指导原则（贯穿全程，先立规矩）

1. **验证优先于建设。** 第一里程碑的目标是"拿到一个 GO/NO-GO 的答案"，不是"把系统写完"。能用最脏的实现回答"方法成不成立"，就不写第二行多余的代码。
2. **每一步都有产出物和判断线。** 每个阶段结束必须能回答一个具体问题（附数字），不能"感觉在推进"。判断线预先写死（见各阶段），到点看数字决定走/停。
3. **先跑通环境，再谈方法。** OSWorld-MCP 环境复现本身是硬工程，是 0 号拦路虎，必须最先清掉。
4. **符号约定沿用 idea 文档**：τ=任务模板、φ=状态签名、α=动作模板；val=边价值=成功率 p × γ^剩余步数 d。详见 idea 文档 §0。

## M1 — 三道清洗 + 三条地基探针（第 1–2 周，方法成不成立的第一道生死线）

> **这是整个 plan 最重要的阶段。** idea 文档反复强调：pilot 第一目标不是"增益+5点"，而是先验证三条地基。因为签名不能归并 / 样本太稀 / 天花板太低，任何一条塌了，方法就是流沙——这三条比增益更底层。

### M1.a 实现三道清洗（必做最小集）
- [ ] **τ 任务模板**：指令 embedding + 槽位抽取，把指令归一到模板。**τ 匹配准确率/召回要专门测**（它决定分册有没有效，不是小事）。
- [ ] **φ 状态签名**：主键 = (app, 归一化 window, dialog)，从 accessibility tree 确定性提取；facts 由 VLM 填、先只做 2–3 个、不进主键。
- [ ] **α 动作模板**：工具 = 工具名+参数槽（精确匹配）；GUI = VLM 一句语义描述，**坐标一律扔掉**。

### M1.b 三条地基探针（跑一批轨迹，只做测量，不做优化）
在 M0 的子集上，用裸 agent 跑一批轨迹存下来，然后离线分析：

**地基① 签名归并纯度** — 方法的地基中的地基
- 问题：同一个 φ 签名下的边，其成功/失败是否真由已记录字段解释？还是被未记录的隐藏状态支配？
- 测法：统计同签名边的成败方差；抽查高方差边，人工看是不是"两个不同局面被记混"。
- **判断线**：多数边的成败能被签名解释（低混叠）→ 地基稳。若普遍混叠 → 签名过粗，MDP/森林地基是流沙，需先修签名（或方法重新定位）。

**地基② 每条边的样本量 n**
- 问题：361 任务 / 3 轮 / 按 τ 分册后，每条边实际能攒到几个样本？
- 测法：画 n 的直方图；看槽位共享能把 n 撑到多少。
- **判断线**：关键边 n 能到 ~5–10 → MC 估计的 p 可信。若普遍 n≤2 → 成功率就是噪声，UCB 压不住，需靠槽位共享/多跑撑厚，或调整分册粒度。

**地基③ 增益天花板（failure-mode 分解）**
- 问题：EvoTree 扔掉坐标、只救"决策类失败"，救不了 grounding 类失败。决策类失败占总失败多少？
- 测法：对裸 agent 的失败轨迹分类：grounding/感知类 vs 决策类（该不该调工具、调哪个、参数错）。
- **判断线**：决策类失败占比决定增益物理上限。若只占 20%，那 +5 点判断线不现实，要重设预期。

**产出物**：一份"地基体检报告"——三条线各一个数字 + 结论。**这份报告直接决定 M2 值不值得做。**

## M2 — 最小闭环 + 前瞻生死线（第 2–3 周）

**前提**：M1 三条地基没有硬塌（至少不是"流沙"级）。

**目标**：搭出"写入→森林→检索→注入"的最小闭环，回答两个生死问题：**(A) 记忆到底有没有用？(B) 前瞻是不是树的真贡献？**

### M2.a 最小闭环（idea §12 必做清单）
- [ ] **写入**：四步 upsert（找状态→找边→更新 n/n_success→成功则倒数记 steps_after_success）。schema 见 idea §0。
- [ ] **森林**：状态按主键索引、边带 to_success 指针（"连起来"的关键，见 idea §4.3）。
- [ ] **检索五拍**：定位→[推荐]算 val 取前2–3→[注意]查 global_notes→拼小抄→工具重排。
- [ ] **前瞻 k=1**：沿 to_success 跳一层，给"这步+下一步"短路径。
- [ ] **global_notes**：工具报错抄一份进全局手册（注意栏）。
- [ ] **write_enabled 开关**：为 Setting II 冻结做准备。

### M2.b 三个关键实验（能回答生死问题的最小集）

**实验 1 — 记忆有没有用（Setting I + 必配对照基线）**
- 3-app 子集跑 Setting I 三轮，看 pass-1/2/3 曲线。
- **⚠️ 必须同跑"记忆禁用、同样重复 3 轮"的对照基线**：EvoTree 曲线减去这条重复效应曲线，剩下的净增量才是记忆的真实贡献（否则 pass-2>pass-1 可能只是任务重复曝光，不是记忆功劳）。

**实验 2 — 前瞻生死线（RQ3，本文结构 novelty 的独木桥）**
- 三个配置对比：`平表+cost-to-go列`（公平基线） vs `森林前瞻关` vs `森林前瞻开`。
- 关键变量是**前瞻开/关**（不是"有没有效率项"——cost-to-go 平表也能存，见 idea 推论 4）。
- **判断线**：前瞻开 vs 关有显著差距，且差距集中在多轮工具任务分桶 → 树的独有价值坐实。若无差距 → 结构 novelty 落空、且撞 REMEMBERER，红灯。

**实验 3 — 注意栏兑现冷启动**
- 全新模板上，只有注意栏（推荐栏空）能否让 agent 避开已知坑 → 验证冷启动。

**产出物**：三个实验各一组数字（Acc/TIR/ACS 三联 + 前瞻分桶曲线）。

## M3 — 决策点（第 3 周末，GO / 缓 / NO-GO）

综合 M1 地基报告 + M2 三实验，对照 idea §15 判断线：

| 信号 | 结论 | 行动 |
|---|---|---|
| 第3轮比第1轮 Acc +5 且 ACS −15%，且前瞻消融显著 | **GO** | 全力推进 M4 全量 |
| Acc +2~3，前瞻有差距但不惊艳 | **缓** | 可做，但要靠分析（失败记忆贡献、TIR→Acc 中介）撑故事 |
| Acc +1 以内，或前瞻无差距，或地基流沙 | **NO-GO** | 止损。三道清洗/账本/检索基建迁移他用，方法重定位 |

**产出物**：一页"GO/NO-GO 决策备忘"——三个数字（地基、增益、前瞻）+ 结论 + 理由。

## M4 — 全量（仅 GO 后启动，第 2 月起）

> 只在 M3 = GO 后展开。这里是重投入，2–3 个月 / 跨一个 ARR 周期，别在拿到 M3 答案前提前烧钱。

- **Setting I 全集**：361 全集三轮，pass-1/2/3 × Acc/TIR/ACS × 多基座（Qwen3-VL 主力 + 一个强闭源）。
- **Setting II**：random split（宽松）+ template-level split（严格），冻结记忆验证迁移；严格档目标——只注意栏版本仍显著赢基线。
- **完整消融**（idea §7 举证表）：去失败记忆 / 去效率统计 / vs flat RAG / vs AWM / vs 全局大账 / 森林vs平表+ctg列 / 前瞻开关 / 只推荐 / 只注意 / 只重排 / 只提示 / VLM强度 / 视觉签名。
- **分析**：按工具数分桶增益、按工具轮数分桶（前瞻贡献）、TIR→Acc 中介、混叠案例、成本核算。
- **晚做升级**（每个配一个消融）：方差报警自动拆分、视觉仲裁、value iteration、前瞻 k=2、子路径折叠、第二环境（generality）。
